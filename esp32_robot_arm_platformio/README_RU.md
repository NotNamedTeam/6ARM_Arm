# ESP32 Robot Arm — VS Code + PlatformIO

**22.10.2026: текущая индивидуальная калибровка — на Python, файл
`manual_calibration.py`. Запускайте задачу VS Code «ESP32: Python — калибровка
по одному». Она использует уже установленную проверочную прошивку A/S/STOP
и НЕ перепрошивает ESP32. Инструкция — в `PYTHON_CALIBRATION_RU.md`.
При старте все сигналы OFF; GO включает только один выбранный привод на
короткое время. Для изменения Python-файла НЕ нажимайте Upload.
Описание Wi-Fi-прошивки ниже относится к отдельному профилю `esp32dev`.**

Проект предназначен для классической платы ESP32 DevKit/WROOM и шести сервоприводов робота из статьи Instructables. В основной прошивке доступны два способа управления одновременно:

- через браузер по Wi‑Fi;
- напрямую по USB из Serial Monitor в PlatformIO.

## Открытие проекта

VS Code 1.140.0, PlatformIO IDE 3.3.4 и PlatformIO Core 6.2.0 уже установлены локально. После перехода на Ubuntu 26.04 PlatformIO Core переустановлен в отдельное окружение Python 3.14; путь к нему задан в `.vscode/settings.json`. Платформа ESP32 и библиотека `ESP32Servo 1.2.1` скачаны, проект успешно собран.

Запустите файл `start-vscode.sh` из этой папки. Он открывает переносимый VS Code сразу с проектом и правильным локальным профилем. Затем:

1. Подключите ESP32 по USB.
2. В нижней панели PlatformIO нажмите **Upload**.
3. После загрузки нажмите **Serial Monitor**.

Если плата не классическая ESP32 DevKit/WROOM, сначала замените `board = esp32dev` в `platformio.ini` и проверьте GPIO в `include/config.h`.

Готовый бинарный файл после сборки находится в `.pio/build/esp32dev/firmware.bin`. Плата подтверждена как классическая ESP32-D0WD-V3.

**15 октября 2026 на плату загружена временная прошивка `esp32-center-d17` для отдельного MG90S.** Она сразу после включения подаёт только на GPIO17 импульс 1500 мкс / 50 Гц и продолжает удерживать середину управляющего диапазона. Остальные выходы не управляются, Wi-Fi отключён. Это не прежняя вертикальная поза плеча 82°: серва центрируется отдельно для сборки. Ответ платы проверен: `CENTER GPIO 17 PULSE_US 1500 HOLD ON`; физический угол вала не измерялся. Прежняя flash-память целиком сохранена в `esp32_before_center_20261015T115435Z_16246.bin`, результат — `gpio17_center_result.json`.

После сборки для обычной калибровки нужно отдельно загрузить окружение `esp32-calibration` (при запуске все приводы отключены); для Wi-Fi — `esp32dev`. Не загружайте другую прошивку при неподдерживаемом весе манипулятора: во время перезапуска удержание пропадает.

В обновлённой временной прошивке команда `TEST` запускает ровно один тест GPIO17: 1000 мкс → 2000 мкс → 1500 мкс, с паузами по 1.5 секунды. При включении платы тест сам не повторяется: задаётся только центр. `STATUS` показывает текущую команду; `CENTER` отменяет тест и задаёт 1500 мкс; `STOP` прекращает тест с удержанием текущей команды. Ответы последнего теста сохранены в `gpio17_endpoint_test.log` и `gpio17_endpoint_test.json`. Это подтверждение команд прошивки, не измерение реального движения сервы.

Для управления этой отдельной сервой в градусах добавлены `DEG 0`, `DEG 180`, `DEG 90` и `STATUSDEG`. Внутри используется `Servo.write(angle)`. Первоначально диапазон был 1000–2000 мкс; после проверки он расширен до крайних значений ESP32Servo: **500–2500 мкс**, середина **1500 мкс**. Пользователь визуально подтвердил ход от 0 до 180° без замечаний; запись находится в `gpio17_calibration.json`. Это относится к отдельному MG90S, подключённому для теста к GPIO17, и не меняет прежние исходные углы собранного робота или постоянное назначение этой сервы.

Команда `PULSE <мкс>` позволяет задать импульс только в диапазоне 500–2500; `LIMITS` возвращает пределы текущей прошивки. За пределы библиотеки не выходили: 300–2700 мкс не применялись. Если после нецентральной команды `PULSE` две секунды нет новых команд, прошивка автоматически возвращается на 1500 мкс. Команда `STOP` отменяет этот возврат и удерживает текущую команду; при механическом упоре питание отдельной сервы следует отключить.

`full_pulses_gpio17_visible.sh` загружает прошивку и выполняет один плавный тест 500 → 2500 → 1500 мкс; `repeat_full_pulses_gpio17_visible.sh` повторяет его **без перепрошивки**. На крайних значениях задержка составляет 0.5 секунды; в конце остаётся удержание середины. Исходный успешный тест сохранён в `gpio17_full_pulse_test.log` / `.json`, повтор — в `gpio17_full_pulse_retry.log` / `.json`. Остальные GPIO не управляются.

## Управление по Wi‑Fi

Без заданных реквизитов домашней сети ESP32 создаёт точку доступа:

- сеть: `RobotArm-ESP32`;
- пароль: `robotarm32`;
- страница: `http://192.168.4.1`.

Чтобы использовать домашний роутер, впишите SSID и пароль в `include/config.h`. IP-адрес появится в Serial Monitor.

## Прямое управление через Serial Monitor

Скорость: **115200**, окончание строки: **Newline**.

Команды основной Wi‑Fi-прошивки (`esp32dev`):

```text
ENABLE       включить сигналы сервоприводов
STOP         немедленно отключить сигналы
STATUS       показать состояние и все углы
S 0 90       сервопривод 0, угол 90°
S 5 45       захват, угол 45°
```

Номера: 0 — основание, 1 — плечо, 2 — локоть, 3 — наклон кисти, 4 — поворот кисти, 5 — захват.

**GPIO19 / ось 4 — привод непрерывного вращения по результату проверки.** Значения меньше/больше 90 задают направление и скорость, а не абсолютный угол. В основной прошивке его управление ограничено коротким импульсом (не более 700 мс) с автоматическим снятием сигнала; отпускание ползунка также отправляет остановку. В проверочной прошивке автоматического ограничения нет: после пробного импульса обязательно отправляйте `STOP 4`.

В проверочной прошивке (`esp32-calibration`) команды другие:

```text
STATUS       показать углы и состояние ON/OFF каждого привода
A 0 0        включить только нижний привод на GPIO16, задать абсолютные 0°
S 0 10       установить абсолютные 10° активного привода
S 0 0        вернуть к абсолютным 0°
STOP 0       отключить только привод 0
STOP         отключить все приводы
```

Для остальных осей используется `A <номер> <угол>` и затем `S <номер> <угол>`. Несколько выбранных приводов могут одновременно удерживать положение; `A` новой оси больше не отпускает предыдущую. Для позиционных приводов углы всегда **абсолютные от нуля сервопривода**, а не прибавляются к текущему положению. Для основания допустимо 0–270°, для остальных 0–180°; это диапазоны команд, не проверенные механические пределы собранного манипулятора. Наблюдаемая пользователем вертикальная поза: основание **0°**, плечо **82°**, локоть **75°**, наклон кисти **30°**; захват открыт при **0°**. GPIO19 в эту позу не включается: он вращается непрерывно.

## Подключение

| Узел | GPIO |
|---|---:|
| Основание / нижний привод | 16 |
| Плечо | 17 |
| Локоть | 5 |
| Наклон кисти | 18 |
| Поворот кисти | 19 |
| Захват | 21 |

Сервоприводы нельзя питать от ESP32. Нужен отдельный стабилизированный источник 5–6 V с током, достаточным для одновременной работы приводов. Минус источника обязательно соединяется с GND ESP32. До первого запуска проверьте механические пределы каждого сочленения; полный диапазон 0–180° может быть опасен для конкретной сборки.
